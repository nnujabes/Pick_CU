# 라벨 기준 초안 (팀 검토용)

- 작성 근거: `data/train_2nut.csv`의 90개 상황만 봤어요. dev 라벨에 맞춰 기준을 만들면 점수가 부풀려지기 때문이에요.
- 상태: 초안이에요. 아래 "결정 필요" 항목은 제가 임의로 정하지 않았고, 원본 CSV도 수정하지 않았어요.

## 1. 지금 라벨에서 일관된 부분

| 문장 신호 | 첫 번째 영양소 |
|---|---|
| 운동, 근육, 단백질 | 단백질 높음 |
| 짜다, 싱겁게, 붓기, 혈압 | 나트륨 낮음 |
| 밥심, 힘 내기, 장시간 활동 전 | 탄수화물 높음 |
| 밥·면 끊기, 탄수 줄이기 | 탄수화물 낮음 |
| 기름진 것, 튀김, 고소한 것이 당김 | 지방 높음 |
| 느끼한 것을 피함, 담백 | 지방 낮음 |
| 많이 먹기, 살 찌우기, 치팅데이 | 열량 높음 |
| 살 빼기, 양 줄이기 | 열량 낮음 |
| 달달한 것이 당김 | 당류 높음 |
| 단 것을 피함, 무설탕, 제로 | 당류 낮음 |

첫 번째 영양소는 문장 신호로 대체로 설명돼요. 흔들리는 쪽은 **두 번째 영양소**예요.

| # | 요청 유형 | 현재 train 라벨 | 정할 내용 |
|---|---|---|---|

## 3. 결정 필요: 문장에 근거가 약한 정답

정답을 상황 단위로 정했기 때문에, 성분을 직접 말한 문장에도 말하지 않은 성분이 정답에 들어가요.

- S033 "나트륨 낮은 걸로 먹고 싶어" → 정답에 당류 낮음이 포함돼요.
- S2021 "지방 많아서 고소한 간식이 뭐가 있을까요?" → 정답에 열량 높음이 포함돼요.
- S2064 "당류 0인 음료를 찾고 있어요." → 정답에 열량 낮음이 포함돼요.

정할 내용: 두 번째 영양소를 "문장에서 추론할 수 있는 것"으로 볼지, "서비스가 함께 적용할 기본 조건"으로 볼지 정해야 해요. 후자라면 신호별 기본 짝을 표로 고정하는 게 좋아요. 그 표가 있으면 모델은 첫 번째 영양소만 뽑고 두 번째는 규칙으로 붙이는 구조도 가능해요.

## 4. dev 라벨을 고칠 때의 원칙

- dev 라벨을 고치려면 **위 기준을 먼저 확정한 뒤**, 모델 점수를 보지 말고 적용해 주세요. 틀린 문장을 보면서 고치면 70%가 나와도 믿을 수 없어요.
- dev를 고칠 때는 원본을 덮어쓰지 말고 새 파일로 만들어요. 그리고 점수를 낼 때 어느 버전인지 함께 적어요.
